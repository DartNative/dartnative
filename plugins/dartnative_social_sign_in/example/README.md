# social_sign_in_example

Example app for **dartnative_social_sign_in** — the same Social Sign-In screen
the framework playground ships, running standalone.

It exercises both providers, each through two button styles:

- **Sign in with Apple** — `ASAuthorizationController` via FFI (iOS only).
- **Sign in with Google** — `GIDSignIn` (iOS) / Credential Manager (Android) via FFI.

Result cards show the returned name, email and a truncated ID token; failures
(cancel, missing capability, missing client ID) are rendered inline rather than
thrown, so the app stays usable while you work through the setup below.

## Run it

```sh
dn pub get
dn run -d <device-id>
```

**It runs unconfigured.** No `GoogleService-Info.plist` is committed and the
Sign in with Apple capability is not pre-enabled — both require credentials tied
to *your* Apple team and Google Cloud project. Out of the box the buttons appear
and report their missing configuration when tapped. Wire up whichever provider
you want to try, per the next section.

The example is an official demo — free to run, no license setup.

Always use **`dn`** for run/build/pub commands — not the underlying SDK CLI.

## Configuring the providers

This example's identifiers, for the console entries below:

|          | Identifier                             |
| -------- | -------------------------------------- |
| iOS      | `com.dartnative.socialSignInExample`    |
| Android  | `com.dartnative.social_sign_in_example` |

### Sign in with Apple (iOS)

Open `ios/Runner.xcworkspace` → select the **Runner** target → **Signing &
Capabilities** → **+ Capability** → **Sign in with Apple**.

The capability needs an *explicit* App ID registered to your team, so if the
bundle identifier above is already taken, change it to one of your own first.
Without the capability, authorization fails with **error 1000** — which the demo
surfaces in the Apple result card.

Apple ships no native Android SDK, so this section is iOS-only. On Android the
demo reports that instead of failing.

### Google Sign-In — iOS

1. Add your `GoogleService-Info.plist` to the Runner target. The iOS client ID is
   read from its `CLIENT_ID` key. That key only exists once the iOS OAuth client
   does — enable the Google provider in Firebase Authentication (or create the
   iOS OAuth client in the Cloud console) and re-download the plist. Setting
   `GIDClientID` directly in `Info.plist` also works and takes precedence.
2. Add the plist's `REVERSED_CLIENT_ID` as a URL scheme in `Info.plist` — that's
   how the OAuth redirect gets back into the app.

### Google Sign-In — Android

Credential Manager needs no config file, but two OAuth clients must exist in your
Google Cloud project:

1. A **web** client — pass its ID at run time, which is what the demo reads:
   ```sh
   dn run -d <device-id> --dart-define=GOOGLE_SERVER_CLIENT_ID=xxxx.apps.googleusercontent.com
   ```
2. An **Android** client matching the package name above and your **SHA-1 signing
   fingerprint** (`./gradlew signingReport` prints the debug SHA-1; in Firebase:
   Project settings → your Android app → *Add fingerprint*). Without it Google
   recognizes no app and issues no credentials.

## Where the code lives

- `lib/social_sign_in_demo.dart` — the whole demo: both flows and the UI. Ported
  verbatim from the playground screen; the only edits are inlining the
  playground's theme-aware palette as dark-mode literals and adding the root
  `App` wrapper.
- `lib/main.dart` — `registerAll()` then `runApp`.
- `lib/dartnative_plugin_registrant.dart` — generated; loads the plugin's FFI
  symbols. Regenerated by `dn pub get`, don't hand-edit.

## Don't touch (unless you know the runtime)

These files are the dartnative runner glue — they're why the app renders:
`ios/Runner/{AppDelegate,SceneDelegate}.swift` + the scene block in `Info.plist`,
and `android/.../{Application,MainActivity}.kt` + the Material3 themes in
`android/app/src/main/res/values*/styles.xml`.
