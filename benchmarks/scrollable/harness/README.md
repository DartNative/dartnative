# The harness

Scripts that scroll the apps the same way and read the platform's own
meters. Each script names its inputs at the top.

| Script | What it does |
| --- | --- |
| `android/run.sh` | Launches an app on a device, scrolls it with Legend List's own `autoscroll.sh` and saves `dumpsys gfxinfo` and `dumpsys meminfo` per run, or a screen recording with `--record`, or, with `--peak`, the app's memory read once a second through the scroll, for its peak. `DIRECTION=both` scrolls back up afterwards with `autoscroll_up.sh`, their script with the gesture reversed; the Chat screen scrolls up only, with that script. |
| `android/scroll_to.py` | The scroll-to test on the advanced Cards screen: presses each app's Scroll button through five cards down the list, two short scrolls and three far ones, and reads from the accessibility tree where each target landed and whether the content jumps while the finger drags back through cards the list may not have drawn. `--chat` runs it on the Chat screen, through five messages up the history. |
| `android/clip.sh` | A 10-second clip of one app scrolling one screen, for sharing: a recorded run cut to the scroll and encoded at 60 fps, 720 x 1600. |
| `android/summarize.py` | Medians and ranges over a batch folder's runs. |
| `android/table.py` | Prints a results table for one screen from the batch folders, the recorded runs' blank counts and the sampled runs' peaks: typical frame time, blank space, memory at rest and at its peak; `--all` adds the slowest frames and the late count. |
| `android/trace.sh` | Records a Perfetto trace of one app under the autoscroll: the scheduler, the frame pipeline, the app's own trace sections. |
| `android/trace_frames.py` | From such a trace: the frame times and what held the main thread longer than a frame. |
| `android/threads.sh` | One run of an app scrolled as `run.sh` scrolls it, with every thread's processor time read from the phone just before and just after the scroll. |
| `android/threads.py` | From those readings: the processor time per second of scrolling on the main thread, on RenderThread and on all other threads, the busiest of those by name, and how many times the React Native app's other threads used each other app's. |
| `blank_area.py` | Counts, frame by frame, the share of a recording's list area that shows the list's own background: what the user saw empty. `--halves` reports a down-then-up run's two halves apart. |
| `ios/autoscroll/` | The driver built into the three iPhone apps (a pod for the DartNative and React Native apps, a source in the Swift one): launched with `BENCH_AUTOSCROLL=<n>`, the app flings its own list n times, the same curve in every app (0.1 s of travel at 4,000 points a second, then UIKit's own deceleration), the content moved by each frame's share of the travel as a finger moves it, its delegate told what a finger tells it; idle in every other launch. Each fling is an `os_signpost` interval, and the driver also writes every fling's times to `Documents/bench_flings.txt`, with how far they went in points and in rows, and a sync reading that its last mark carries too, which is how `trace_summary.py` places the flings on the trace's time line: the device's log daemon lets a process's marks into a recording only from some tens of seconds in, and the run's last mark is the one every trace has. `BENCH_DIRECTION` picks the way (`down` for the Chat screen, `both` to come back), `BENCH_BLANK=1` counts, every frame inside the flings, the share of the list's visible height that shows no content: the screen is read in horizontal bands of 4 points, a band is covered when a drawn view crosses it anywhere across the width (so a chat's own space beside a bubble is covered by the bubble), and an empty stretch taller than a row gap is missing content, a row not drawn yet or a sticker whose animation has not been built; written after the last fling to `Documents/bench_blank.txt` as the mean, the worst frame, the frames more than half blank, and the blank time, the share weighted by each frame's time on screen, in milliseconds per second of scrolling, the unit of hitch time; the count costs the main thread about a millisecond a frame, so a blank run is a run of its own, `ios/blank.sh`; `BENCH_BLANK=2` also writes the list's tree in the first frames more than a tenth blank, for checking the count against it; `BENCH_WATCH=1` makes no flings and counts blank rows in every frame the list moves under a finger (a UI test's, `ios/flick.sh`), writing the count once a second; `BENCH_SPEED=<points/s>` sets the speed the finger lets go at (4,000 without it); `BENCH_UNIFORM=<seconds>` makes one steady scroll at that speed for that long instead of the flings (`UNIFORM=<s>` in `ios/trace.sh` and `ios/blank.sh`), a trial that packs the same work into a quarter of the time and is not what the results use; and `BENCH_MEMORY=1` writes a census of the app's memory ten seconds after the last fling: the footprint, the dirty memory by the kind of allocation with the sizes its regions come in, the footprint once the free malloc pages are given back, the malloc heap by class, by block size and by how full its regions are, the window's largest layers, and the app's own account of its runtime heap when it writes one (the DartNative app writes its Dart heap's counters to `Documents/bench_heap.txt` once a second under the same flag). METHODOLOGY.md says why the app flings itself and not a UI test. |
| `ios/run.sh` | Runs the XCUITest in `ios/ScrollRunnerUITests` that swipes an app on a connected iPhone and records Apple's scroll metric over five launches. Not used for the results: its swipes make UIKit build every row of a `UITableView` between them (METHODOLOGY.md); the results use `trace.sh`. |
| `ios/capture.swift` | Records the screen of an iPhone connected by cable, as QuickTime Player's movie recording does, for a set number of seconds. The first recording makes iOS ask whether headphones were connected; the UI test answers "Other Device" before it starts. |
| `ios/clip.sh` | A 10-second clip of one app scrolling one screen on a connected iPhone, for sharing: the screen recorded over the cable while the UI test swipes, the ten seconds with the most movement cut out (`ios/motion_window.py`) and encoded at 60 fps, 720 wide. |
| `ios/summarize.py` | Per-launch values and medians from the metric files. |
| `ios/blank.sh` | The blank-space run on the iPhone: the same flings with `BENCH_BLANK=1` and no recording, and the driver's count copied next to the trace (`<app>_<screen>_blank.txt`: the mean, the worst frame and the blank time in milliseconds per second of scrolling). |
| `ios/flick.sh` | Blank rows under a real finger: the UI-test runner flicks the list with real touches (`testFlicks`, `SPEED` and `PAUSE` as knobs) while the app, launched in the driver's watch mode, counts blank rows in every frame the list moves. Nothing is timed in it, for the reason "No UI test around the flings" gives in METHODOLOGY.md. On both screens, by the driver at 4,000 to 15,000 points a second and by real touches at 6,000 to 12,000, Legend List drew every row it passed but a few frames; the blank rows the recordings show come with the Scroll button's long scrolls. |
| `ios/trace.sh` | One run of 25 flings the app makes itself (`ios/autoscroll`), under Instruments (os_signpost, Hitches, Display, Time Profiler, Activity Monitor), which launches the app itself with the flags in its environment; copies the driver's fling times and memory census next to the trace. `SWIPES=<n>` for fewer flings, `DIRECTION=both` as for the Android harness; `SETTLE=<s>` lengthens the recording for an app that takes longer than 8 s to show its list. |
| `ios/scroll_to.sh` | The scroll-to test on the iPhone, on the Chat screen or the advanced Cards screen: taps each app's Scroll button through the same five targets as on Android (UI test `testScrollTo`) and reports, in points, how far each landed from where it was asked to rest. |
| `ios/trace_summary.py` | From such a trace, inside the flings: the typical frame time (the median of the app's update for each frame), the hitches and their time, the frames the app showed a second, the panel's refresh rates, the app's CPU time (main thread and all threads), and its memory footprint at rest (the census's own reading) and at its peak before the census began. |
| `apps.sh` | Which installed app each script launches: every screen of every app is an app of its own ("ChatList (RN - FlatList)", `com.legendapp.listtest.chat.flatlist`), opened straight on that screen, so the scripts launch it by its id. |
| `chart.py` | Draws the results charts from the tables in `RESULTS.md`: one measure on both phones, a 1920 × 1080 PNG. |

The iOS test project is generated with XcodeGen from `ios/project.yml`;
`run.sh` and `trace.sh` generate it when it is missing. Run the iOS
scripts with the Xcode that built the apps selected (`DEVELOPER_DIR`): a
newer Xcode's `xctrace` may not find the phone's processes.
